## 1. ติดตั้ง Apps Script

1. เปิดไฟล์ **Spa Queue**
2. ไปที่ **ส่วนขยาย → Apps Script**
3. สร้างหรือเปิดไฟล์ \`Code.gs\`
4. นำเนื้อหาจาก \`apps-script/Code.gs\` ไปวางแทนโค้ดเดิม
5. เปิด **Project Settings** และเปิดการแสดงไฟล์ Manifest
6. นำเนื้อหาจาก \`apps-script/appsscript.json\` ไปใส่ใน \`appsscript.json\`
7. บันทึก
8. เลือกฟังก์ชัน \`installSpaQueueSystem\` แล้วกด **Run**
9. อนุญาตให้ Script เข้าถึง Google Sheets และส่งอีเมล (ใช้เฉพาะเมื่อกำหนด ALERT_EMAIL)

หลังติดตั้ง ระบบจะสร้าง/เตรียมแท็บ:

- \`SPA_CONFIG\`
- \`SPA_SYSTEM_LOG\`
- \`SPA_EXPORT_AUDIT\` (ซ่อน)
- แท็บสำรองชื่อขึ้นต้น \`SPAQ_BACKUP_\` จะถูกสร้างก่อน Reset

## 2. ตรวจชื่อหมอนวดใน SPA_CONFIG

ระบบไม่เพิ่มคอลัมน์ในแท็บ \`ตารางเวลาหมอนวด\`

ใน \`SPA_CONFIG\` ด้านคอลัมน์ D–G จะมี:

| Therapist_ID | Registry_Name | Active | Note |
|---|---|---|---|
| 1 | ชื่อเต็มสำหรับทะเบียน | TRUE | |
| 2 | ชื่อเต็มสำหรับทะเบียน | TRUE | |
| 3 | ชื่อเต็มสำหรับทะเบียน | FALSE | |

ระบบจะพยายามค้นชื่อเดิมจากคอลัมน์ **พนักงานนวด** ในทะเบียน โดยจับชื่อเล่นในวงเล็บ เช่น \`(เมล)\` หรือ \`(ภา)\` หากหาไม่พบจะใช้ชื่อไทยจากแท็บหมอนวดและแจ้งให้ตรวจสอบ

ก่อนเริ่มใช้งานจริง ให้ตรวจว่า \`Registry_Name\` เป็นชื่อเต็มที่ต้องการลงทะเบียน

### การเปลี่ยนหรือเพิ่มหมอนวดภายนอก

1. เพิ่มแถวใหม่ในแท็บ \`ตารางเวลาหมอนวด\`
2. ใส่ ID ใหม่ที่ไม่ซ้ำ, Name_TH, Name_EN, Photo_URL และ Working_Today
3. จากเมนู **42C Spa System** เลือก **จัดแถวหมอนวดให้ครบ**
4. ตรวจชื่อเต็มใน \`SPA_CONFIG\`

ไม่ต้องเพิ่มคอลัมน์ใหม่ในแท็บหมอนวด

## 3. Deploy Web App

1. ใน Apps Script กด **Deploy → New deployment**
2. เลือกชนิด **Web app**
3. Execute as: **Me**
4. Who has access: **Anyone**
5. กด Deploy
6. คัดลอก URL ที่ลงท้ายด้วย \`/exec\`
7. ใส่ URL ในไฟล์ \`spa-v2/config.js\` ที่ค่า \`apiUrl\`

ตัวอย่าง:

\`\`\`js
window.SPA_DISPLAY_CONFIG = Object.freeze({
  apiUrl: 'https://script.google.com/macros/s/DEPLOYMENT_ID/exec',
  refreshMs: 10000,
  staleAfterMs: 35000,
  criticalAfterMs: 120000,
  hotelName: 'The Chic Hotel',
  displayTitleTh: 'ตารางคิวสปา',
  displayTitleEn: 'SPA QUEUE'
});
\`\`\`

## 4. วิธีกรอกข้อมูลประจำวัน

พนักงานกรอกข้อมูล **เฉพาะแท็บ Queue ในไฟล์ Spa Queue**

คอลัมน์ที่ระบบอ่าน:

1. \`Therapist_ID\`
2. \`Time_Slot\`
3. \`Status\`
4. \`Customer_Note\` — ใช้เป็นชื่อลูกค้าในทะเบียน
5. \`ห้อง\`
6. \`เบอร์โทร\`
7. \`คอร์สการนวด\`
8. \`ชั่วโมง\` — ใช้อ้างอิงใน Queue แต่ไม่ใช้คำนวณชั่วโมงส่งออก
9. \`ราคา\`
10. \`ประเภทลูกค้า\`
11. \`หมายเหตุ\`
12. \`เวลาเริ่มจริง\`
13. \`เวลาสิ้นสุดจริง\`
14. \`พนักงานขาย\`

คิวจริงอย่างน้อยต้องมี:

- Therapist_ID ที่จับคู่ชื่อทะเบียนได้
- ชื่อลูกค้า
- คอร์สการนวด
- เวลาเริ่มจริง
- เวลาสิ้นสุดจริง
- สถานะต้องไม่เป็น ว่าง/เปิดห้อง/ปิดห้อง

เบอร์โทรและห้องเป็นข้อมูลประกอบ Booking ID แต่ไม่บังคับ เพื่อรองรับ Walk-in หรือกรณีที่ไม่มีเบอร์โทร

## 5. ความหมายสถานะ

- **ว่าง / Available** — รับคิวได้
- **ไม่ว่าง / Occupied** — มีลูกค้า
- **คิวสุดท้ายของวัน / Last Booking** — ลูกค้ารายนี้เป็นคิวสุดท้ายของหมอนวด เวลาสิ้นสุดจริงต้องไม่เกิน 23:00 และหลังจบคิวหน้า Display จะแสดงปิดห้องสปาอัตโนมัติ
- **เปิดห้องสปา / Spa Open**
- **ปิดห้องสปา / Spa Closed**

ระบบไม่แก้สถานะของแถวคิวสุดท้ายทันทีหลังจบ เพราะต้องเก็บหลักฐานต้นทางไว้ตรวจ Export; การเปลี่ยนเป็น “ปิดห้องสปา” เกิดบนหน้า Display และข้อมูลต้นทางจะถูกล้างหลังการตรวจครบถ้วนตอน 10:00

## 6. ลำดับ Export และ Reset

### 09:00

- อ่านคิวของ Business Date เดิม
- แยกคิวจริงออกจากแถวต่อเนื่อง
- สร้าง/เปิดแท็บทะเบียนของเดือนนั้น
- เพิ่มคิวใหม่หรืออัปเดตคิวเดิมด้วย Booking ID
- ตรวจว่าทุก Booking ID อยู่ในทะเบียน

### 09:30

- ทำงานซ้ำแบบ Idempotent
- เก็บคิวที่เพิ่มหรือแก้หลังรอบแรก
- ไม่สร้างรายการซ้ำ

### 10:00

- อ่านข้อมูลใหม่อีกครั้ง
- ถ้าพบ Booking ID ที่ยังไม่มีในทะเบียน ระบบพยายาม Export ซ้ำ
- ถ้ายังขาด หรือข้อมูลต้นทางไม่สมบูรณ์ ระบบบล็อก Reset
- ถ้าครบ ระบบสำรอง Queue เป็นแท็บซ่อน
- ล้างเฉพาะข้อมูลลูกค้าและตั้งสถานะเริ่มต้น
- เปลี่ยน Business Date เป็นวันปัจจุบัน

## 7. การทดสอบก่อนเปิดจริง

1. ใน Apps Script รัน \`runSpaQueueSelfTest\`
2. รัน \`validateSpaQueueSystem\`
3. ใส่คิวทดสอบหนึ่งคิวที่มีเวลาจริงไม่ตรงชั่วโมง
4. รัน \`manualExportNow\`
5. ตรวจแท็บเดือนในทะเบียน
6. แก้ราคา/หมายเหตุแล้วรัน Export ซ้ำ ต้องเป็นการอัปเดตแถวเดิม
7. ทดสอบคิวสุดท้าย 22:00–23:00 ชั่วโมงต้องเป็น 1 และช่อง 23:00 ต้องแสดงปิด
8. ทดสอบลบ Booking ID ในทะเบียนแล้วรัน \`manualVerifyAndResetNow\` ระบบต้อง Export ซ้ำหรือบล็อก Reset
9. ตรวจว่า Display ไม่มีข้อมูลลูกค้า ห้อง เบอร์โทร ราคา และหมายเหตุ
10. หลังผ่านทั้งหมดจึงนำหน้า V2 ขึ้นแทนหน้าเดิม

## 8. การเปิดใช้งานบน GitHub Pages

ระหว่างพัฒนา ไฟล์ใหม่อยู่ที่ \`spa-v2/index.html\` และยังไม่แทน \`index.html\` เดิม

เมื่อผ่านการทดสอบ:

1. ใส่ Web App URL ใน \`spa-v2/config.js\`
2. ตรวจหน้า Display จากข้อมูลจริง
3. คัดลอกหน้า V2 ไปเป็น \`index.html\` ที่ root
4. Merge เข้า \`main\`
5. ตรวจ GitHub Pages อีกครั้งบน TV

การวางระบบบน branch แยกช่วยให้ระบบเดิมยังใช้งานได้จนกว่าจะอนุมัติ Cutover
